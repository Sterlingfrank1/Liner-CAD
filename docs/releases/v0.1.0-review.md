### v0.1.1 候选：Viewer 自动打开、选择同步到对话、迭代速度（2026-11-13 试用后提出，已决策方向，尚未开始）

起因：用户 2026-11-13 在 Claude Code 本机试用，让 Claude Code（Sonnet 5.5）与 dsh（DeepSeek-V4.1-Flash high）各出两张图：有模板的牛鼻立铣刀（样例 `牛鼻铣刀.dxf`，改尺寸）、无模板的 Y90S-4 电机外形图。四张图 `lcad check` 均 0 error。三个问题由此而来；数据与四张图在仓库之外的 `D:\Industry\Claude-Code\lcad-demo\`（`report.html`、`results\`、`run_demo.py`），不入库。

| 试用数据（每格 n = 1，四个运行并发） | Claude 牛鼻刀 | dsh 牛鼻刀 | Claude 电机 | dsh 电机 |
|---|---|---|---|---|
| 耗时 | 100 s | 675 s | 274 s | 900 s |
| 新处理 token（输入 + 输出 + 缓存写） | 67 k | 177 k | 105 k | 228 k |
| 模型步数 | 18 | 124 | 23 | 142 |

lcad 自身在这些图上 `build` 约 1–1.7 s、`check` 约 1–1.4 s、`render` 约 2–3 s、`context` 约 1.1 s：**迭代慢在模型轮次，不在 lcad**。观察到的两个缺口：`lcad template import` 对样例 DXF 只抓到图框 / 标题栏，两边最后用的都是自带 A3 图框；四次运行都没有打开 Viewer。

用户 2026-11-13 的决定：参数化模板做成“用户自己 `lcad template save` 沉淀”；提示钩子只装 Claude Code，dsh、opencode 等其余 Agent 先走“复制引用”。做法仍是方向，每条先验证再做，各留回归用例；范围、拆分和先后由总体计划安排。

**A. 首次出图自动打开 Viewer**（对应问题 1）

- 现状：`lcad view` 自己会开浏览器（`--no-open` 关闭），提交后页面自动刷新；但没有任何东西会自动启动它，skill 只写了“用户开着 Viewer 时”怎么办。
- 做法：harness 层处理，不靠模型记得去运行。某个图纸目录第一次 `build` / `edit` 成功后，若没有 Viewer 在运行，就起一个**后台常驻**的 Viewer 并打开浏览器一次；已在运行则只刷新，不再开新标签。端口、pid 记在 `.linercad/` 下（git 不跟踪）。命令输出的 JSON 里带 `viewer: {url, opened}`，打不开浏览器时 Agent 能把地址告诉用户。
- 约束：Agent 执行命令时没有 TTY，不能靠 TTY 判断是否交互；要有明确开关（环境变量 / `--no-view`，`CI` 环境默认关）。常驻进程要有空闲超时自退，避免遗留进程。仍只监听 127.0.0.1，令牌加固仍在 v0.2（见下），常驻后暴露时间变长，是这条要一并评估的风险。
- 待验证：dsh 的沙箱（`workspace-write`）能否拉起后台进程和浏览器；远程 / 云端会话打不开本机浏览器时的降级（只给地址）。
- 验收：Claude Code、dsh、opencode 各出一张图，Viewer 打开（或输出里有可用地址）；第二次提交不再开标签；空闲后进程退出。

**B. Viewer 选择同步到对话框**（对应问题 2）

- 现状：选中元素（含多选）已写入 `selection.json`，但要 Agent 自己跑 `lcad context @sel` 才读到——Agent 来取，不是 Viewer 推过去。输入框里的“芯片”取决于各个 Agent 的界面是否开放接口，lcad 做不到，也不该绑某个 Agent。
- B1 复制引用（所有 Agent）：Viewer 加“复制引用”按钮和快捷键，把当前选择生成 `@D.d1（Φ25k6，主视图） @D.d2（…）` 一行，粘进任何 Agent 的输入框；skill 已认得这种写法。与上面 Viewer 界面条目 2（空态说明里的 `@ID` 复制）合并做。
- B2 Claude Code 提示钩子（只装 Claude Code）：`lcad skill install --target claude` 同时往项目 `.claude/settings.json` 合并一个“提交提示时”的钩子，把 `selection.json` 的当前选中（ID、类型、一句话描述）作为附加上下文带进这条消息；没有选择、选择已过期（版本号落后或超时）时什么都不带。用户只要在 Viewer 里选好再打字“改成 k6”。合并要幂等、不覆盖用户已有设置。
- 约束：钩子每条消息都会跑，`lcad context` 实测约 1.1 s，钩子不能走完整 `lcad` 启动，要做成只读 JSON 的轻量入口。
- 不做：把 lcad 做成 MCP 或在输入框里真正出现芯片，等宿主开放接口或把 Viewer 嵌进 VS Code 面板，放 v0.2 以后；dsh、opencode 等其余 Agent 只走 B1。
- 验收：多选 3 个元素 → 复制引用粘进 dsh 一轮能改对；Claude Code 里不复制、直接打字也能改对；无选择时消息不被改动。

**C. 后续迭代要快**（对应问题 3）

- C1 `lcad template save <名>`：用户自己把一张画好的图沉淀成参数化模板。保存 `drawing.py`（`Param` 即参数表）、可选 `model.py`，加一个清单（名称、描述、参数及范围）。之后 `lcad init <目录> --from <名> [--set D=8 R=1 …]` 一步出图，再 `lcad build` 改参数；`lcad template list` 与 skill 都要列出用户模板，并写一条规则：用户需求与已有模板匹配时，从模板起步、改参数，不重画。这样“第一次慢、之后快”，也是核心竞争力 2（临时脚本沉淀）的落地。
  - 待定：保存位置（用户级目录，加环境变量覆盖；与企业档 `templates/<名>.toml` 的关系）；修订层 `drawing.actions.jsonl` 里的标注微调怎么处理（建议只存构建层，修订层存在时给出提示）；模板图不含临时调整，`save` 前要求 `lcad check` 0 error。
  - 验收用例：牛鼻刀——首次出图（Claude 100 s / dsh 675 s）→ `save` → 换规格（如 D6 R0.5）再出图；目标是模型步数和耗时都明显下降，具体阈值先测基线再定。
- C2 尺寸类修改不经过模型：Viewer 拖滑块（每次约 1–2 s）再点“写回源码”，这条已有；Viewer 界面条目 1（滑块刻度和范围）是它的体验前提，一起做。
- C3 减少每轮多余步骤：`lcad edit --dry-run`（M3 已记为缺口：只出 changed / findings / 渲染，不写日志不提交）；skill 加一条“check 已无 warning 就不为美化反复 render”；dsh 的推理强度（现为 high）加一组低档对照。
- C4 先把迭代速度量出来：试用用的 `run_demo.py`（`claude -p --output-format stream-json` 与 `dsh --json` 事件流，统计耗时、token、工具调用、lcad 子命令）并入 `evals/cross_agent.py`，作为评测指标方案 §3.5 P 过程（每轮耗时 / token）的数据源；同时区分“每轮新开调用”和“同一对话连续修改”两种口径（上一轮评测全是前者，是最坏情况）。
