# Liner-CAD v0.1.0 发布说明

2026-11-09 · tag `v0.1.0` · 范围：`DESIGN.md` §10 的 M0–M3（“之后”一行不在 v0.1 内）

Liner-CAD 是给 Coding Agent 用的通用 2D 工程图 harness（包 `linercad`，命令行 `lcad`）。它本身不是 Agent，内部不调 LLM。Agent 现写 Python、现跑；harness 负责画法、布局、检查、DXF 输出、Viewer 和 git 版本。

## 安装

```bash
git clone https://github.com/Sterlingfrank1/Liner-CAD && cd Liner-CAD
uv sync                 # 核心依赖：ezdxf、matplotlib
uv sync --extra 3d      # 可选：3D 来源与装配图（build123d）
uv run lcad skill install --target claude --dir <Agent 工作目录>   # 或 codex / opencode / generic
```

## 四个核心竞争力在 v0.1 的落点

1. **专业度 harness 强化与制造信息索引。** 规定画法是内核工具；标准数值来自资源库并注明标准号；尺寸、公差、基准、形位公差、粗糙度、组件、序号都是带 ID、可在 `model.json` 查询的语义元素；Checks 五个规则包；评测集 L1 / L2 / L3 共 40 例。
2. **临时脚本层与 coding。** 构建层 `drawing.py` + 修订层 `drawing.actions.jsonl`；Agent 写 `apply(d)` 临时脚本，`lcad edit` 事务执行，失败时给元素 ID、原因、数值和候选且不留痕迹；每次成功修改 = 一个以用户原话为标题的 commit。
3. **Viewer 人机交互。** 人点选、拖滑块；Agent 读 `selection.json` / `snapshot.json` / `lcad context @sel`；版本列表与叠加对比。
4. **harness 定位。** 核心依赖只有 ezdxf 和 matplotlib，3D 为可选；Skill 可装进 Claude / Codex / OpenCode / 通用 Agent。

## 质量

- 干净 clone（`uv sync --extra 3d`）：947 个测试全绿，ruff 通过，评测 40 / 40（零 error，几何对照 1.0，箱体完整性对照 1.0）；CI（Linux / Windows / 3d）绿。
- 每个里程碑都经过 SPEC 独立评审（G1）、卡片 TDD 与 PR 评审、G5 验收（含只拿 Skill 的独立 Agent 多轮修改、独立多模态出图评审）和监督会话的干净 clone 复核（G6），记录见 `docs/ROADMAP.md` §5。
- 跨 Agent 评测（M3，每项 n = 1）：Claude Sonnet 只拿装好的 Skill，与同一模型裸写 ezdxf 相比，出图观感相当；首图更快（箱体 94 s 对 472 s，叉架 123 s 对 366 s，装配持平）、检查全过、PMI 是语义元素、每轮修改有版本；修改轮次比基线慢（25–95 s 对 16–44 s）。详见 `docs/milestones/M3/evidence/cross-agent.md`。

## 已知缺口

- **出图：** 独立评审对新范例和装配图多为 2–3 / 5。主要问题是尺寸排布（放射状直径引线、多层尺寸）避让弱，序号没有对齐和最小间距，装配图没有螺纹啮合画法，3D 和装配视图不能出局部放大，明细栏不合并相同零件。
- **3D：** 不支持阶梯剖、旋转剖和移出断面（用 2D 画法补）；投影边编号按位置排列，参数一变 `diff` 就显得很乱。
- **DXF 导入：** TEXT 导入成带引线的注释，HATCH 被跳过；验收只用了 ezdxf 生成的样例。
- **跨 Agent：** Codex 部分没有运行，本机 Codex 的服务商返回 403 余额不足，OpenCode 没有有效的 key。重跑命令见 M3 HANDOVER §5。
- **资源库：** 缺 GB/T 3、GB/T 6403.5、B 型中心孔数据。**（发布后已补，2026-11-09：** `res.thread_undercut` / `thread_runout`、`res.grinding_groove`、`res.center_hole("B", d)`；数据来自公开网页转录，不是标准原文，各表的来源、核对方式和 `verified` 标记见 `src/linercad/res/*.toml` 的 `[meta]`。GB/T 6403.5 只有 1986 版手册表一个来源，标为未核对；GB/T 3 内螺纹表同样单一来源。同时按新数据改了 `shaft` 范例和 L2 `shaft` / `pump_shaft` 的退刀槽尺寸。**）**

## 待用户人工评审（汇总 M0–M3 HANDOVER）

- 出图质量：各里程碑 `evidence/*.png` 与 `render-review.md`。是否把尺寸布局作为 v0.2 第一优先级。
- 标题栏分格（GB/T 10609.1、ISO 7200）与投影符号画法。
- 资源库数据来源（`src/linercad/res/*.toml` 的 `[meta].source`），尤其是键槽深度偏差（JIS B 1301 = ISO 773）和基准字母禁用集。
- Viewer：交互手感（点选容差、缩放平移、滑块防抖），界面评审余下的几条，本地服务的安全设计（令牌、Host / Origin 校验、只绑 127.0.0.1）。
- 跨 Agent：是否接受“出图观感与裸 ezdxf 相当，优势在首图速度、检查、语义和版本”这个定位；给 Codex 服务商充值或更换后，重跑 Codex 部分。
- 是否提供一份有明确许可的第三方 CAD DXF，作为导入验收样例。
