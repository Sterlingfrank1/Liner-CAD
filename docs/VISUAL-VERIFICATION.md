# 视觉验证契约（v1.0）

2026-11-21 · 适用于 v0.1.1 起的全部卡片与 V1 验收 · 代码：`src/linercad/visual.py`，测试：`tests/visual/`

这份文档只回答一件事：**Agent 看图这一环，怎样才算数。** 它不管规则（`lcad check`）、不管结构化数据（`snapshot.json` / `@ID`），只管"把图给人看、给模型看"这一段的可信度。

## 0. 分工：图做什么，不做什么

| 手段 | 负责 | 不负责 |
|---|---|---|
| `snapshot.json` / `@ID` / `lcad check` | 坐标、数值、公差、规则违反（可精确到 0.001 mm） | 观感、拥挤、留白、像不像一张工程图 |
| **图（PNG / PDF 页）** | 线型、剖切、标注是否互相压住、有没有明显画错、整体观感 | **一切数值判定**（0.05 mm 级视觉不可判，别试） |

**规矩一：** 每张卡的验收 = 结构化 diff（主）+ 图（辅）。只交图不交 diff，或只交 diff 不交图，都算没验收。
**规矩二：** 看图结论必须写出**具体观察对象**（元素 ID / 位置 / 读到的数值），"目视检查通过"不是结论，是口头禅。
**规矩三：** 交图必须附 `sha256` + 像素尺寸；`ink_ratio < 0.002` 的图一律判失败——空白图能通过任何"看不出问题"的评审。

## 1. 导出：文件层面必须先对

| 项 | 契约 | 现状 |
|---|---|---|
| 页幅 | **页面像素 = 图幅毫米 × dpi / 25.4**；A3@150 dpi = 2480×1753 px（5.9 px/mm） | 2026-11-21 修复：此前 ezdxf 的 `adjust_figure` 把图缩到 matplotlib 默认 4.8 in 高，A3 只有 1018×720（**2.4 px/mm**，2.5 mm 字只有 6 px） |
| 颜色 | 黑线、白底；`focus_id` 红；不接受白底白线（"干净"其实是空的） | 已由实体属性覆盖函数固定为 `#000000` |
| 墨量 | 真实 A3 图 `ink_ratio` 实测 0.031–0.047；门槛 `MIN_INK_RATIO = 0.002`（约 15 倍余量） | 已测 |
| 纯注释图 | 模型空间只有文字也必须出墨；修复前该场景 `ink_ratio = 0.0` | 已修复并有回归测试 |
| PDF | 一页 = 一张图幅，A3 = 1190.55×841.89 pt；PDF 不是图，必须先光栅化（PyMuPDF，`linercad[visual]`） | 已测 |
| 局部图 | `focus_bbox` 裁片默认 300 dpi（11.8 px/mm） | 已测 |

一条命令的记忆法：**150 dpi 全幅看整体，300 dpi 裁片看数字。**

## 2. 可读性预算：像素下限

`MIN_TEXT_PX = 14`：低于 14 px，数字"能读"只是因为你预期它写什么（实测 8–10 px 的 `Ø20 H7` 会读对，但 `±0.05` 与 `±0.5` 会混）。
`MARGINAL_TEXT_PX = 8`：低于 8 px 只是"这里有字"，不得据此下任何结论。

| 字高（mm） | 150 dpi（全幅） | 300 dpi（裁片） | 600 dpi |
|---|---|---|---|
| 1.8（标题栏小字） | 10.6 px ⚠ 仅"有字" | 21.3 px ✅ | 42.5 px |
| 2.5（GB 注释） | 14.8 px ✅ 刚好过线 | 29.5 px ✅ | 59.1 px |
| 3.5（尺寸数字） | 20.7 px ✅ | 41.3 px ✅ | 82.7 px |
| 5.0（标题 / 图号） | 29.5 px ✅ | 59.1 px ✅ | 118.1 px |

推论，也是硬规矩：

- **2.5 mm 及以下**：裁片（`lcad render @ID`，300 dpi）之后才允许下结论。
- **1.8 mm**：全幅永远不够，必须裁片，且只用于"有没有、在哪"，不用于读数。
- **大图会被归一化**：1785×1440 的 PNG 进模型时会被压成 webp（约 60 KB）。所以别指望"一张超大图管全部"，**分区裁片比整版超采样可靠**。

2026-11-21 的判读实测（供校准，不是指标）：阶梯图中 8 px 起可辨认固定串，14 px 起任意数字稳定；盲测 3 张 1400 px 图，注入的"多余孔"被检出，两张无缺陷图无虚报（3/3）。

## 3. 符号与字体：空框不是"没问题"

| 事实 | 后果 |
|---|---|
| 栅格文字用 ezdxf 解析出的 TTF：`LC` 样式 → `simfang.ttf`（28522 字形，含中文），`Standard` → 回退字体（3506 字形，**不含中文**） | 中文注释依赖 simfang 在本机可用 |
| **U+2316 ⌖ 在两个字体里都没有** | 形位公差符号**必须矢量绘制**，绝不能用字符；空框在图上看起来像"没有标注" |
| 缺字形不会报错，只会画一个方框 | 必须主动检查：`missing_text_glyphs(doc)` |

守门测试：`test_example_text_has_no_missing_glyphs` 逐样式核对示例图全部文字；`test_glyph_guard_catches_a_known_missing_character` 钉住"⌖ 确实不在字体里"这个前提，字体哪天变了测试会提醒我们放宽。

## 4. Agent 看图的标准动作

1. `lcad render <dir>` → 全幅 150 dpi，看：视图布局、剖切与剖面线、标注是否互相压住、有没有漏画的边。
2. 需要读数值 / 公差 / 粗糙度 → `lcad render <dir> @ID`（裁片 300 dpi，被看的元素标红）。
3. 外部 PDF（用户样例、供应商图）→ `linercad.visual.rasterize_pdf(pdf, out.png, page=n, dpi=150)`。
4. 结论按这个形状写（进证据文件）：

```json
{
  "image": ".linercad/tmp/render-D.L.png",
  "sha256": "…",
  "size": [424, 989],
  "observed": ["Ø20 孔居中于左端面上方", "R8 圆角存在且光滑", "120 尺寸线与轮廓不交叉"],
  "suspects": [],
  "verdict": "ok"
}
```

**禁止**：拿 `snapshot.json` 的数字冒充"看图结论"；只说 "ok / 已目视检查"；用整幅图给 1.8 mm 字下读数结论。

## 5. 已知盲区（诚实清单，别装作看不见）

- **0.05 mm 级公差**：像素级不可能判，必须走结构化数值。
- **拥挤 / 交叉 / 引线斜穿**：视觉只能粗判"明显不舒服"，量化交给 `D.place` / `A.place` 指标（E5）。
- **细线在低 dpi 消失**：0.25 mm 线宽在全幅 150 dpi 下约 1.5 px，会断；需要看线型时一律裁片。
- **剖面线密度、线型比例、箭头大小**：属于"专业观感"，仍需 V1 人工评审兜底；视觉只做第一道筛。
- **颜色 / 灰度印刷效果**：当前只导黑白，不做灰度评审。
