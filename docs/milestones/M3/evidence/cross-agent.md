## 结论（如实）

- **出图观感两者相当。** 中等复杂度的这三张图，Sonnet 只用 ezdxf 也画出了合格的三视图、剖视、明细栏；单看渲染分不出明显高下。
- **harness 更好的地方**：首图快得多（箱体 94 s 对 472 s，叉架 123 s 对 366 s；装配持平）；检查全部通过、warning 更少（基线被查出封闭尺寸链与重复尺寸）；尺寸、基准、形位公差、粗糙度、组件、序号都是带 ID 的语义元素，可查询、可被 Viewer 点选和下一轮引用；每轮修改是一个带原话的 commit，可 `lcad diff` / `undo`。
- **harness 不如基线的地方**：修改轮次更慢（Claude 每轮 25–95 s，基线 16–44 s——基线只改一行常量重跑脚本，harness 要读 context、写临时脚本、重建投影与检查）；装配任务首图没有更快。
- **偏向**：箱体任务和范例 `gear_cover` 很像，Claude 直接从范例起步，这对 harness 有利。
- **评测中发现并修好的 harness 缺陷**：装配里同一标准件放在多个位置时，第二件在剖视中丢失（缓存形体被 `Compound(children=)` 重新挂父，#66 修复并加回归测试）；修复后重建的图两侧螺栓、螺母都在。
- **导入器的不足**（影响基线导入后的样子，不影响上表的检查数）：TEXT 导入成带引线的注释、HATCH 被跳过、原图框被保留在新图幅里。
