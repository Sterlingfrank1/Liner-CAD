- 版本：v2.0（按 2026-11-26 复核意见简化：**取消 sheet/drawing 双形态、卡片并为 3 个 PR**）
- 基线：`lcad v0.1.2`（`74d4b84`）；目标版本：`v0.1.3`
- 上游：`v0.1.3-REQ.md v1`、两轮评审、用户 2026-11-26 复核意见

## 1. 版本目标

**v0.1.3 = 让 Viewer 真正成为出图流程的一部分 + 让一张图能沉淀成项目里的"图纸程序"。**

三件事：

1. **首图即有 Viewer**：回复里默认给可点地址；面板可调、可收起；左键框选；标题栏/参数表都能点选；能直接下载产物。
2. **图纸模板可沉淀**：用户确认满意（或一句话指示）→ `lcad template save` 存进项目 → 下次 `init --from` 换参数直接出图；模板带修订层，换参数不跑版。
3. **样式可脚本化**：标题栏/表格的字号、对齐、换行、列宽、边框、Logo 能通过 API 改，且守住 GB/T 10609.1。

## 2. 锁定决策

| ID | 决策 | 理由 |
|---|---|---|
| D1 | `LCAD_NO_VIEW=1` 保持原语义（完全不起 Viewer）；新增 `--ensure-viewer` / `--no-viewer` | 保护既有 CI |
| D2 | **显式 CLI 覆盖环境变量**：`--ensure-viewer` 在 `LCAD_NO_VIEW=1` 下仍生效 | 否则 Agent 按旧 skill 设变量时静默失效（本轮 bug 根因） |
| D3 | 模板 = **构建层 + 基线修订层**（`drawing.py` + `baseline.actions.jsonl`），实例化时合并进 `drawing.actions.jsonl`（`edit="e0"`）。**已定为 A 方案：两文件包，v0.1.3 不做单文件合并** | 复用 `record.replay`，runtime 零改动；单文件 squash 推迟到 v0.1.4 之后 |
| D4 | **模板只有一种形态**：一个图纸程序 + 可选基线。**不做** `kind: sheet|drawing`、不做 `init --sheet` | 用户明确：空图框也只是"一个只有图框的 drawing.py"，让 AI 决定吸收什么 |
| D5 | 项目根**优先取 Agent 传入的工作区根**（`--project` 或 `LCAD_PROJECT_ROOT`）；未传时向上找 marker（跳过图纸自身的 `.git`，遇 `.git` 查完再停）；仍未找到且 `cwd` 是图纸目录 → 用 **`cwd.parent`**。**永不把标记/模板建在图纸目录内部** | lcad 只看得到每条命令的 cwd，必须让 Agent 显式给根，兜底才推断 |
| D6 | 下载 **无副作用**（不 commit / 不打 tag / 不改修订号）；正式归档仍 `lcad export` | 修订号是发版语义 |
| D7 | v0.1.3 **不做**参考 DXF/PDF 自动复刻、不做 codegen（把修订层折成单文件，即 B 方案）、不做矢量 Logo | 复杂度收益比不划算；B 方案推迟到 v0.1.4 及以后 |
| D8 | **卡片按域合并为 3 个 PR**：Viewer 全量 / 项目模板 / 样式与 Logo | 与 agy 最初的 PR-1 思路一致，降低管理粒度 |
| D9 | 模板的 **tag 是标签**（写进 `template.json` 的字符串），**不是 git tag**；模板目录属于**用户的图纸项目**，与 Liner-CAD 开发仓无关；`lcad` 不在用户项目里 commit / 打 tag | 图纸项目的版本管理与 lcad 的发布 tag 是两套东西，不能混 |

## 4. 明确不做

- `kind: sheet|drawing` 双形态、`lcad init --sheet`、模板"种类"路由。
- 参考 DXF/PDF → 模板自动复刻（PDF 解析/OCR）。
- 把修订层 codegen 成单文件 `drawing.py`（B 方案，推迟到 v0.1.4 及以后）。
- 表格/标题栏行列边框线单独 ID 化与点选。
- 多用户/远程 Viewer、鉴权加固、STEP/PMI、资源库内化。

## 5. 与你最初需求的覆盖核对

| 你的原始要求 | 覆盖 | 说明 |
|---|---|---|
| 确认满意/一句话指示 → `lcad template -save`，把"首次生图 + 临时脚本迭代"的最终版本固化 + tag，后续换参数直接出图、低 token、可离线调参 | **PR-2（R9/R10/R11）+ PR-1（R8 下载）** | 模板 = `drawing.py` + `baseline.actions.jsonl` 一个包；`init --from --set` 换参数；Viewer 调参后可下载 |
| 首次出图回复里默认给 Viewer 地址 | **PR-1（R1）** | `--ensure-viewer` + skill 约束 |
| 面板边缘拖宽；检查器一键收起/展开 | **PR-1（R3）** | 含窄屏两档 |
| 中间画布：点选、滚轮缩放、左右键平移 → **去掉左键平移，改左键框选** | **PR-1（R4）** | 右键保留平移；中键可选 |
| 检查器文案 `1 个已写入 selection.json · Ctrl+Alt+C` 的困惑 | **PR-1（R6）** | 只留"已选中 N 个元素" |
| 标题栏表格 Viewer 不可点选；要能点选每格、改内容/字体/换行/表格样式/放 Logo；参数表同样 | **PR-1（R7 点选）+ PR-3（R13/R15 样式与 Logo）** | 点选先落地，样式随后 |

**已确认（A 方案）**：模板是**两文件包**——`drawing.py` + `baseline.actions.jsonl`，`init --from` 时自动合并成新图的 `drawing.actions.jsonl`。行为上与"合并后的单文件"等价：换参数即可出图、可交给别人、可直接读改。

- 包内两文件是**一个单元**，文档与 `lcad template list` 写明；只拷 `drawing.py` 会丢修订层，`init` 时提示。
- **B 方案（`--squash` 生成单文件）推迟到 v0.1.4 及以后**，不进 v0.1.3。

**tag 语义（D9）**：`lcad template save --tag r1` 只把 `r1` 写进 `template.json`，用于 `list`/`init` 输出与人工识别；**不打 git tag**。模板落在**用户自己的图纸项目**目录（`<project>/lcad-templates/`），是否提交由用户在该项目仓库里决定，`lcad` 不替用户 commit，也与 Liner-CAD 开发仓的 tag 无关。

## 6. 里程碑验收（G5）

1. 干净 clone：`pytest` 全绿、`ruff` 通过。
2. 首次出图场景：`--ensure-viewer` 返回可用 URL；`LCAD_NO_VIEW=1` 下仍返回；`--no-viewer` 下不返回。
3. 交互场景：框选 60 个元素 → 状态栏提示 + `@sel` 返回摘要；标题栏空格可点选。
4. 模板场景：保存 → 新目录 `init --from` → `check` 0/0 + `model_hash` 一致 → `--set` 改 3 组参数仍 0 error → `undo e1` 不动基线。
5. 下载场景：三格式可下；`git status` 空、无新 tag。
6. 样式场景：改标题栏字号触发 GB warning；带 Logo 图四路一致。
7. 收口场景：`main` 全绿、版本号 0.1.3、`docs/releases/v0.1.3.md` 存在；`scripts/release.py 0.1.3 --dry-run` 通过后，由 **DSH** 执行正式发布。
