# M1 BRIEF：专业深度（轴套类、盘盖类）

> 写给 M1 里程碑会话。流程、门禁和**精简规则**见 `docs/ROADMAP.md`（§4.1–4.2 优先）；设计依据见 `DESIGN.md`（下文 § 均指它）和 `DRAFTING-COVERAGE.md`；M0 的交接见 `docs/milestones/M0/HANDOVER.md`。

## 1. 目标

在 M0 的骨架上把**专业度**做出来：轴套类、盘盖类两族零件的图，在规定画法、视图表达、尺寸 / 公差 / 形位公差 / 粗糙度 / 技术要求上达到合格工程图的水平。

同时建立两件长期资产，它们是核心竞争力第 1 条的基础，也是 v0.2 大规模评测的起点：

- **资源库**：机器可读的标准数据，每条注明标准号和版本；
- **评测集**：L1 / L2 用例和批量运行器。

## 2. 范围

| 模块 | 内容 | 依据 |
|---|---|---|
| 资源库 | 极限与配合（GB/T 1800.1/.2 ↔ ISO 286）、未注公差（GB/T 1804 ↔ ISO 2768）、普通螺纹（GB/T 193 / 196 / 197）、平键与键槽（GB/T 1095 / 1096）、中心孔（GB/T 145）、退刀槽和越程槽（GB/T 3、GB/T 6403.5）、矩形花键（GB/T 1144）。能由标准公式算出的（IT 公差、基本偏差、螺纹基本尺寸）用公式加抽样校核，查表类才录表。只录数值，不录标准原文 | COVERAGE §2.3 |
| 尺寸体系 | 对齐尺寸、角度尺寸、倒角注法；链式 / 基准式；尺寸链：显式分组 + 表达式图，封闭环公称值和公差（极值法、均方根法），封闭 / 冗余 / 缺失检查；参数覆盖检查 | §4.4 |
| 语义 PMI | 公差与配合：代号 → 上下偏差（查资源库），三种注法（代号 / 偏差 / 两者）；基准；形位公差（特征项目、公差值、基准、修饰符）；粗糙度（参数、数值、加工方法、“其余”）。都是带 ID、分字段、关联被测几何的元素，不只是一段文字（v0.2 输出 STEP AP242 PMI，见 ROADMAP §6） | §4.2 |
| 规定画法第一批 | 内外螺纹（含螺孔、不通孔）、中心孔、退刀槽 / 越程槽、键槽、花键：内核工具，参数取自资源库，产出语义元素，并配检查规则 | COVERAGE §2.1 |
| 视图 | 半剖、局部剖、阶梯剖、旋转剖、移出 / 重合断面、局部放大（从父视图自动裁剪、放大、标注）、斜视图。尽量共用一套机制：剖切面（可多段）+ 剖面线 + 标注 | §3.4 |
| 模板与标准档 | GB/T 10609.1 标题栏、GB/T 14689 图幅；ISO 档（ISO 7200 标题栏，第一角 / 第三角及识别符号）；企业档叠加：`lcad template import` | §4.7、§7 |
| Checks v1 | drafting / dimensioning / tolerancing / surface / layout 五个规则包，每条规则注明标准号；`accept(rule, id, reason)` | §4.5 |
| 零件族卡片 + 范例 | 轴套类、盘盖类各一张卡片（由 `SKILL.md` 路由加载，只写判断和取舍）；每族 2–3 个范例，可 `lcad init --from` | COVERAGE §2.2 |
| 评测集与运行器 | L1：规定画法单项，参数化生成。L2：两族各 5–10 个零件，每个有需求描述、build123d 3D 模型、参考 `drawing.py`。运行器批量执行，输出汇总指标（违规数、几何对照结果、一次通过率、修改轮数）；加用例不改代码 | COVERAGE §2.4、ROADMAP §6 |
| 3D 几何对照工具（开发期） | build123d HLR 投影与 2D 视图逐线比对，判断图形画对没有；只给开发和评测用，不进用户接口；3D 依赖为可选 | §3.4 |

**顺带修掉 M0 的遗留：** PNG 粗细线对比弱；轴上 Φ 文字有的在轮廓内、有的在外；`lcad build` 输出缺 `changed`；完整 GB 标题栏取代简化版；SKILL 修订后还没有被独立 agent 重新用过（M1 的 agent 评测会覆盖）。

**不做：** 叉架类、箱体类、装配图、3D 正式来源、DXF 导入（M3）；Viewer（M2）；大规模评测（v0.2）。

## 3. 验收（G5）

1. **覆盖：** 两族的 L2 参考图全部自动检查零 error，几何对照通过；每族 2–3 个范例进入范例库。
2. **Agent 实测：** 一个独立 agent 只拿 `SKILL.md`（含零件族卡片）和需求描述，每族从零画出至少 2 个 L2 零件，再各做 3 轮以上修改。记录违规数、修改轮数，作为基线（v0.2 起做大规模评测）。
3. **标准档：** 同一个零件分别按 GB 和 ISO 出图，都通过规则检查；叠加企业模板后，模板规定的做法不被判成违规。
4. **规定画法：** 第一批每一项都有 L1 用例，自动检查通过。
5. **PMI 语义：** `model.json` 里公差、形位公差、基准、粗糙度元素分字段存放、关联被测几何，有测试覆盖。
6. **出图评审：** 独立的多模态 agent 按评分表评审范例图，结论写进 HANDOVER；需要用户看的列进“待用户人工评审”。
7. CI 通过，HANDOVER 合并，tag `v0.1-m1` 已推送。

## 4. 留给 SPEC 决定

1. 资源库的格式和位置（建议包内数据文件 + 很薄的查询 API），以及哪些用公式算、哪些录表。
2. PMI 元素的字段 schema，以及与被测几何的关联方式。
3. 各种剖视、断面、局部放大怎么共用一套机制。
4. 评测用例的目录结构、运行器的输出格式、几何对照的判定阈值。
5. 零件族卡片的路由方式和篇幅。
6. 分几组 PR 推进。建议：资源库 + PMI + 尺寸链 → 规定画法 + 视图 → 标准档 / 模板 + Checks v1 → 卡片、范例、评测集 + 3D 对照 → G5。

## 5. Goal 条件

> M1 done when: SPEC merged; all M1 PRs merged with CI green; shaft/sleeve and disc/cover families reach coverage (L2 reference drawings have zero check errors and pass 3D geometry comparison; 2–3 examples each); an independent agent using only SKILL.md draws ≥2 L2 parts per family from scratch and edits each 3+ rounds; one part passes checks in both GB and ISO; render review recorded; HANDOVER merged; tag v0.1-m1 pushed.
